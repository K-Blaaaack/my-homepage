> **K-Black Homepage · Arknights Visual System**

> **用途**：让未来的 AI 助手或管理员在 5 分钟内接手本站的视觉系统 —— 知道"为什么长这样"、"数值从哪来"、"改哪里"、"别踩哪些坑"。

## 0. 一句话总览

本站视觉遵循 **鹰角（Hypergryph / 明日方舟）品牌语言**，实现集中在单个文件：

```
assets/css/main.css   —— 13 节结构，全站表现层唯一入口
```

> **近黑墨底 + 白纸文字 + 单一青色信号 + 0 圆角 + 1px 细线 + 45° 切角**

**核心原则：证据驱动，不靠感觉。** 每一个色值、字号、时长都能追溯到公开来源（见 §8），而不是"我觉得这样比较方舟"。

## 1. 风格定位

### 1.1 目标调性

| 关键词 | 设计体现 |
|---|---|
| 冷峻 | 近黑灰阶、硬朗几何、零圆角 |
| 档案感 | 编号系统、时间戳、分类标签、1px 分割线 |
| 终端感 | 等宽数字、扫描线、状态指示、双语微标签 |
| 克制 | 单一信号色占画面 <15%，其余全为灰阶 |
| 功能性 | 装饰必须是功能性的（索引、刻度、取景框），不为装饰而装饰 |

### 1.2 ⚠️ 最容易搞错的一点

**方舟 UI 不是"低饱和藏蓝灰调"。** 曾安装过一个名为 `arknights-design-style-guide` 的技能，它给的主色是 `#3F72AF` 哑光藏蓝、基底 `#1A1C20` 中灰，并明文禁止衬线体与粒子效果 —— **这三条都与真实方舟不符**，已卸载。

真实方舟的底色是**近黑 `#080a0b`**，信号色是**亮青 `#18d1ff`**（PRTS 终端就是这个色），另有一枚**酸性绿 `#c8eb21`** 专用于"成功/可用"。

### 1.3 布局骨架的选型（附一次翻车记录）

`ark-ui` 的 Ark 家族配方写的是：

> Shell: **black top bar**, edge utilities, large art stage, lower metadata baseline.

**黑色顶栏**才是方舟家族的 shell。侧边轨道（side rail）是通用章节里的备选分支，且规范区间为 **64–96px**。

> ⚠️ 曾经做过一版 **232px 的左侧导航轨**——既偏离了 Ark 家族配方（应为顶栏），又是它自己引用的规范上限的 2.4 倍。已回退。**引用了数值就要照做，不能引 64–96 却写 232。**

## 2. 设计令牌

全部定义在 `assets/css/main.css` 第 02 节 `:root` 内。**改色只改这里，不要在组件里写死色值。**

### 2.1 墨阶（背景，近黑非纯黑）

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--ink` | `#080a0b` | 舞台基底 / 页面背景 |
| `--ink-2` | `#0e1112` | 面板 / 卡片 |
| `--ink-3` | `#141819` | 浮层 / 悬停底 |
| `--ink-4` | `#1a1f21` | 激活底 |
| `--rule` | `#242a2d` | 1px 分隔线 |
| `--line` | `#333b3f` | 边框线 |
| `--line-h` | `#4a5459` | 悬停边框 |

### 2.2 纸阶（文字）

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--paper` | `#f4f6f6` | 一级：标题 / 核心数值 |
| `--paper-2` | `#c3cbcd` | 二级：正文 |
| `--muted` | `#8d9396` | 三级：注释 / 时间戳 |
| `--disabled` | `#5a6165` | 禁用 |

### 2.3 信号色与状态色

| 令牌 | 色值 | 用途 | 约束 |
|---|---|---|---|
| `--signal` | `#18d1ff` | 选中 / 进度 / 主操作 / 链接 | **单屏占比 <15%** |
| `--signal-d` | `#0f9dc4` | 按下态 | |
| `--state` | `#c8eb21` | 成功 / 可用 / 徽标 | 仅表状态，不作装饰 |
| `--warn` | `#e0a34a` | 损耗 / 倒计时 | |
| `--danger` | `#e0524f` | 危险 / 失败 | |

> **信号色是点睛色，不是铺底色。** 一个界面里它只应聚焦在 1–2 个核心交互点。

### 2.4 字体栈

```css
--cjk:     "Noto Sans SC","Source Han Sans SC","HarmonyOS Sans SC","MiSans","PingFang SC",…,sans-serif;
--display: "Arial Narrow","Roboto Condensed","DIN Condensed","Bebas Neue","Hanson Bold",var(--cjk);
--tech:    "Space Grotesk","IBM Plex Sans","Outfit",system-ui,var(--cjk);
--serif:   "Noto Serif SC","Source Han Serif SC","Playfair Display",Georgia,serif;
--mono:    "IBM Plex Mono","JetBrains Mono","SFMono-Regular",Consolas,monospace;
```

**全部走本地回退，不自托管 WebFont** —— 未安装则逐级降级，零额外网络请求。若要保证效果需自托管（注意 HarmonyOS Sans / MiSans 的授权）。

### 2.5 字距阶梯

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ls-display` | `-.045em` | 巨型显示标题（收紧，工业铭牌感） |
| `--ls-title` | `-.025em` | 模块标题 |
| `--ls-body` | `0` | 正文 |
| `--ls-caps` | `.12em` | 大写英文标签 |
| `--ls-micro` | `.16em` | 微标签 / 导航项（放开，技术标签感） |

### 2.6 切角

```css
--cut-lg:14px; --cut-md:10px; --cut-sm:7px; --cut-xs:4px;
```

**零圆角。** 45° 精确直线切割，方向统一为**左上 + 右下**，同界面不混用。

### 2.7 动效时长

```css
--t-fast:.18s;  /* 直接交互 */
--t-base:.28s;  /* 状态切换 */
--t-slow:.35s;  /* 页面级 */
--t-reveal:.7s; /* 区块显现 */
--ease:cubic-bezier(.22,.8,.2,1);
```

**禁止 `elastic` / `bounce` / `back` 等回弹缓动。**

### 2.8 纹理（生成式，非位图）

```css
--stripe: repeating-linear-gradient(-45deg,rgba(244,246,246,.14) 0 2px,transparent 2px 6px);
--grid-4: linear-gradient(rgba(244,246,246,.028) 1px,transparent 1px), …;
--noise:  url("data:image/svg+xml,…feTurbulence…");   /* 4% */
```

## 3. 布局系统

### 3.1 顶栏

固定顶栏 56px，`rgba(8,10,11,.86)` + `backdrop-filter: blur(14px)`，底部 1px `--rule`。

导航项前置 **`NN` 索引**（CSS 计数器自动生成），选中态为底部 **2px 信号色线**：

```
K-BLACK  K-BLACK.TOP     01 INDEX 首页  02 POSTS 文章  03 STACK 技术栈 …
                         ▔▔▔▔▔▔▔▔▔▔▔▔
```

### 3.2 Hero（主视觉舞台）

- **左下锚定**，不是居中
- 显示标题 `clamp(64px,15vw,190px)`、`line-height:.82`、`letter-spacing:-.045em`
- `margin-left:-.055em` 让字形左端**刻意溢出画布被 `overflow:hidden` 裁切**
- 滚动提示放右边缘，避让左下标题块

### 3.3 区块

`.sec` 最大宽度 1200px 居中，桌面 `padding: 88px 64px`。

区块标题由三部分组成：

```
01 / PROFILE 档案  ▨▨▨▨──────────────────────────────
↑NN 索引   ↑双语标签   ↑45° 警戒线标尺 + 1px 细线
```

**计数器挂在 `.sec-hd` 上**（不是 `.sec`）—— 这样没有标题的区块自然不占序号，且不依赖 `:has()`。

| 组件 | 规格 |

## 5. 动效

| 场景 | 实现 |
|---|---|
| 区块显现 | `opacity 0→1` + `translateX(-14px)→0`，700ms |
| 按钮 / 列表悬停 | 背景色过渡 180ms |
| Tab 下划线 | `scaleX(0)→1`，原点在左，280ms |
| PRTS 启动动画 | 逐行显现，每行 0–5200ms 延迟，仅首页播放，cookie 记录 5 分钟冷却 |

### ⚠️ 5.1 绝对禁止：用 `clip-path` 做隐藏态

**这是本项目踩过的最严重的坑，导致线上全站内容不可见。**

```css
/* ❌ 致命写法 */
.rv{ clip-path: inset(0 100% 0 0); }   /* 元素可见面积为 0 */
```

元素被完全裁剪后**可见面积为零，IntersectionObserver 不再报告相交**，于是 `.vis` 永远加不上 —— 内容永久不可见，且没有任何报错。

```css
/* ✅ 正确写法：只用不影响相交判定的属性 */
.rv{
  opacity:0; transform:translateX(-14px);
  transition:opacity var(--t-reveal) var(--ease), transform var(--t-reveal) var(--ease);
  animation:rvSafe 0s linear 3s forwards;   /* 兜底：观察器失效也会强制显现 */
}
.rv.vis{ opacity:1; transform:none; }
@keyframes rvSafe{ to{ opacity:1; transform:none; } }
```

**兜底动画是硬性要求** —— 任何"依赖 JS 才能显示"的内容都必须有 CSS 层的失效保护。

## 6. 无障碍

```css
:focus-visible{ outline:2px solid var(--signal); outline-offset:2px; }
@media(prefers-reduced-motion:reduce){ /* 全局降级，关闭一切持续动画 */ }
```

- 交互目标 `min-height: 44px`
- `.rv` 由 JS 添加 —— JS 失效时元素正常可见（渐进增强）
- 图标链接保留文字内容作为无障碍名称，**不得用 CSS 隐藏文字来做纯图标导航**

## 7. Logo 与图标资产

### 7.1 字体子集化流水线（1.1MB → 3.7KB）

原始 logo SVG 里内嵌了两份 **base64 WOFF2 字体**（`EndfieldFont` = 汉仪菱心体 95W，`HarmonyOSBlack` = HarmonyOS Sans SC Black），字形是活的 `<text>` 而非轮廓，所以 1081 KB 里 99.7% 是字体数据。

**只用到 17 个字符**，因此子集化：

```bash
# 1) WOFF2 解包（沙箱装不了 brotli C 扩展 → 用 node 内置 brotli 搭桥）
#    .logo/shim/brotli.py 暴露 decompress/compress/MODE_FONT 给 fontTools
# 2) 子集化
pyftsubset font.ttf --text='小破站' --flavor=woff2 \
  --layout-features= --no-hinting --desubroutinize --output-file=out.woff2
# 3) 把 SVG 里 @font-face 的 base64 替换为子集
```

结果：**1081 KB → 3.7 KB（-99.7%）**，浏览器渲染完全一致（浏览器认 data URI 形式的 `@font-face`）。

### 7.2 ⚠️ 命令行渲染器不认内嵌字体

`resvg` 与 `rsvg-convert` **都会跳过 `@font-face`** 并回退到系统字体（Times New Roman），产出错误的位图。要命令行渲染必须：

1. 用 fontTools 把子集字体的**族名改成 SVG 里 `font-family` 引用的名字**
2. 写一份 workspace 内的 `fonts.conf`，用 `FONTCONFIG_FILE` 指过去
3. `fc-cache -f` 后渲染

而浏览器直接渲染则无需任何处理 —— 所以**校验渲染优先用无头浏览器截图**。

### 7.3 图标资产清单

| 文件 | 尺寸 | 说明 |
|---|---|---|
| `static/img/logo-square.svg` | 1024×1129 | 顶栏（透明底） |
| `static/img/logo-wide.svg` | 2048×617 | 页脚（透明底） |
| `static/favicon.ico` | 16/32/48/64 | 多尺寸 |
| `static/favicon-16/32/48.png` | — | 透明底 |
| `static/apple-touch-icon.png` | 180 | 透明底 |
| `static/icon-192/512.png` | — | 透明底 |

> **透明底 logo 是白字** —— 在浅色浏览器主题下 favicon 会看不见。如需兼容浅色主题，应提供 `media="(prefers-color-scheme: light)"` 的深色底变体。

## 9. 踩坑记录（血泪史）

| # | 症状 | 根因 | 解决 |
|---|---|---|---|
| 1 | **线上全站内容不可见**（导航/徽标可见，其余全黑） | `.rv` 用 `clip-path:inset(0 100% 0 0)` 做隐藏态 → 可见面积为 0 → IntersectionObserver 不报告相交 → `.vis` 永不添加 | 改回 `opacity`+`transform`，并加 3s 兜底动画 |
| 2 | Cloudflare 构建失败 `can't evaluate field Data` | 本地 Hugo 0.166，CF 是 **0.147.7**；`hugo.Data` 是 0.156+ API | 改用 `.Site.Data`（仓库既有约定），**改动前先确认目标 Hugo 版本** |
| 3 | `/stack/` 导航不高亮 | 顶层 leaf bundle 的 `.Type` 是 `"page"` 而非 `"stack"`，`.Section` 为 `""` | front matter 显式声明 `type: "stack"` |
| 4 | 宽屏高窗口下三列卡片被压成单列 | `@media(…),(orientation:portrait)` 单独作断点会误判 | 改为 `(max-width:1024px) and (orientation:portrait)` |
| 5 | 区块编号错位（`02 / PROFILE`） | 无 `.sec-hd` 的公告区仍占用序号；`:has()` 方案不稳定 | 计数器挂到 `.sec-hd` 上 |
| 6 | 样式改了但线上不生效 | CSS **未做指纹化**，`/css/main.css` 固定 URL + `max-age=14400` → 老 CSS 配新 HTML | 加 `fingerprint`，URL 变 hash 后浏览器必然拉新 |
| 7 | logo 1.1MB | SVG 内嵌整份 CJK 字体 | 子集化到用到的 17 字形（§7.1） |
| 8 | 命令行渲染出的 logo 字形错误 | `resvg`/`rsvg-convert` 跳过 `@font-face` | 字体改名 + workspace fontconfig（§7.2），或用浏览器校验 |
| 9 | favicon 在浅色主题下不可见 | 白字透明底 | 待办：补浅色主题变体 |
| 10 | 启动动画的 cookie 判定两处不一致 | 两个文件用了不同的 key（`prts_played` vs `prts_loaded_at`） | 统一 key；**跨文件共享的状态必须同名** |

## 10. 操作手册

### 10.1 改颜色

只改 `assets/css/main.css` 第 02 节 `:root`。**不要在组件里写死色值。**

### 10.2 加一个新区块

模板里写 `.sec` + `.sec-hd`，序号自动生成，无需手工编号：

```html
<div class="sec" id="xxx">
  <div class="sec-hd"><div class="sec-tag">XXX 标签</div><div class="sec-line"></div></div>
  …
</div>
```

### 10.3 本地预览

```bash
hugo server --port 1313 --renderToMemory   # 见下方注意
```

> ⚠️ `--renderToMemory` 用于绕过 `public/` 里的历史权限问题。**新建的 content/layouts 目录需要重启 server 才会被监听**。

### 10.4 渲染校验（唯一可靠手段）

```bash
# 用一张延迟响应的图片拖住 load 事件，让截图发生在 JS 执行、观察器回调之后
# 服务器：/slow.gif 路径 sleep 5s
firefox --headless --no-remote --profile /tmp/p \
        --window-size=1440,1000 --screenshot out.png http://localhost:8899/page.html
```

**单纯截图会在 load 时触发，早于 IntersectionObserver 回调 —— 会误判成"内容不可见"。**

### 10.5 加新 logo / 图标

# 附录 A · 鹰角品牌语言（`ark-ui-skill / design-language.md` 萃取）

> 来源：`Brandon030722/ark-ui-skill`，基于鹰角**线上生产站点**逆向整理。
> ⚠️ 该来源自身声明：证据仅覆盖**公开 Web 前端**，`Do not infer the company's internal game UI stack from marketing websites.`

## A.1 六条共享语法

鹰角系产品的家族相似性**不是某一套配色**，而是一种组织信息与图像的方式：

| # | 原则 | 含义 |
|---|---|---|
| 1 | **舞台 + 仪表**（Stage plus instrumentation） | 让全出血图像、抽象场景或大幅排版场充当"舞台"；导航、状态、操作、元数据一律**贴边停靠**，像在给舞台装仪表 |
| 2 | **编辑式层级**（Editorial hierarchy） | 一个超大显示语句 + 一堆小标签/索引/时间戳/双语注记。**大与极小共存，中间尺寸的填充物要少** |
| 3 | **系统虚构**（System fiction） | 导航与元数据要像"属于那个虚构世界的操作系统"，但**必须映射到真实产品任务** |
| 4 | **非对称平衡**（Asymmetric balance） | 强左/右或上/下配重，用细线、留白、次级轨道来补偿 |
| 5 | **受控点睛**（Controlled accent） | 绝大多数表面保持中性，**一个信号色**承载选中、进度或主操作 |
| 6 | **层叠扁平**（Layered flatness） | 纵深来自遮罩、裁切、半透明黑、细线、混合模式、文字叠压 —— **不是光泽卡片** |

## A.2 构图规则

**桌面**

- 顶栏预留 **56–96px**，或侧轨预留 **64–96px**
- 主图像/内容场保持不被打断，工具只挂在它的**周界**上
- 主视觉与操作控件用 **60/40 或 70/30** 的大分割
- 显示标题锚定在**下三分之一或边缘**的基线上，配紧凑元数据
- 1px 网格线**克制使用**以建立坐标；**绝不要把每个模块都做成描边卡片**
- 允许显示文字与插画在视口边缘**被刻意裁切**

**竖屏**

- 用紧凑顶栏、底部操作条或折叠菜单**替换**侧轨
- 重新编排图层，**不要把桌面的绝对坐标等比缩小**
- 主操作与标题保持可见且不重叠
- 竖排文字**只作次级装饰**，绝不用于必要指示

## A.3 排版规则

**生产中观察到的字体族**：Source Han Sans、Source Han Serif、Bender、Oswald、Novecento Sans Wide、Gilroy、Space Grotesk、Trajan、Sumerhan 及产品专有字体 —— **多数字体授权不明**，除非项目已获授权，否则使用安全替代：

| 角色 | 安全字体栈 |
|---|---|
| CJK UI | `"Noto Sans SC","Source Han Sans SC","PingFang SC",sans-serif` |
| 窄体显示 | `"Arial Narrow","Roboto Condensed","DIN Condensed",sans-serif` |
| 技术拉丁 | `"Space Grotesk","IBM Plex Sans",system-ui,sans-serif` |
| 档案衬线 | `"Noto Serif SC","Source Han Serif SC",serif` |
| 等宽数据 | `"IBM Plex Mono","SFMono-Regular",Consolas,monospace` |

**规则**

- 微标签与章节名用**大写拉丁**
- 显示标题要**紧**：`line-height: .82–.95`，`letter-spacing: -.02em ~ -.08em`
- 微标签要**开**：`letter-spacing: .08em ~ .18em`
- CJK 正文保持常规字距与舒适行高
- 主 CJK 与次级英文放在**不同行或清晰基线**上，不要到处撒无意义的英文
- 索引、计时、坐标、计数一律用**等宽数字**（tabular numerals）

## A.4 色彩规则

| 家族 | Ink | Paper | Signal | 可选 State |
|---|---|---|---|---|
| **Ark**（本站采用） | `#080a0b` | `#f4f6f6` | `#18d1ff` | `#c8eb21` |
| Endfield | `#191919` | `#f2f2f0` | `#fffa00` | `#00ffa2` |
| Ex Astris | `#080914` | `#f3f2ef` | `#46f6e6` | `#925dff` |
| POPUCOM | `#141414` | `#fffdf4` | `#ffcc1a` | `#3994ff` |
| Corporate | `#050505` | `#f3f3f3` | `#f3ff00` | — |

- **中性表面占构图 75% 以上**
- 信号色只用于：激活态、进度、选中导航、**一个**主操作
- **不要**在浅底上把信号色用作长正文
- 图像舞台上优先用 **45%–88% 的半透明黑遮罩**，而不是玻璃白卡片
- 即便参考站用的是"烤进图里的文字"，真实文本仍要测 WCAG 对比度

## A.5 几何与纹理规则

- 默认圆角 **0**；允许的功能性圆角 `2–4px`
- 默认边框 `1px solid currentColor` 或中性 alpha
- 用 **45° 切角、窄斜杠、角标括号、斜切楔形**作方向指示
- `clip-path` 用于**揭示与剪影**，不要用来把每个容器都做成不规则形
- 用遮罩把滚动区域与媒体边缘**淡入舞台**
- 网点、点阵、纸纹、图线一律**低透明度**，且**自己生成 CSS/SVG 纹理**
- 混合模式只在文字仍可读且**有回退方案**时使用
- 优先自绘线性图标或统一开源图标集，线宽保持 **1.5–2px**

## A.6 动效规则

观察到的模式：遮罩揭示、横向背景滚动、裁切擦除、呼吸信号块、短促方向抖动、漂浮角色层、1.6–2s 滚动提示。

| 场景 | 时长 |
|---|---|
| 直接交互 | **180–350ms** |
| 区块显现 | **500–900ms** |
| 克制的注意力循环 | **1.6–2.4s** |

- `steps()` 只用于精灵图或数据跑马灯
- UI 反馈位移 **4–16px**；更大位移留给整屏切换
- `prefers-reduced-motion: reduce` 下**暂停或移除**非必要循环
- **不要**让所有状态变化都只靠透明度淡入 —— 该有方向感或裁切感时要加上

## A.7 组件配方

| 组件 | 规格 |
|---|---|
| **导航轨** | 固定边缘轨，含图标、紧凑标签、**激活信号条**与可选索引。激活态**不能只靠颜色**区分（需填充/指示器/字重） |
| **区块标题** | 大号窄体标题 + `NN / NN` + 小号双语副标题 + **延伸进留白的细线**。内容用语义 HTML，装饰放伪元素/SVG |
| **技术面板** | 扁平或透明表面 + **一条强边** + 头部代码 + 正文 + 状态行。**避免四边圆角卡片外壳** |
| **操作按钮** | Ark/Endfield：**方角 + 强标签 + 左侧信号条或楔形 + 1px 描边** |
| **媒体网格** | 让封面图主导，统一裁切比例，元数据简短，悬停覆盖层安静 |
| **状态条** | 沿边缘放版本、连接状态、坐标或任务进度。**只用真实信息，绝不编造无意义遥测来填空间** |

## A.8 无障碍要求

- 使用语义化 landmark / button / link / heading / list
- 焦点可见：**2px 信号色描边 + 偏移**
- 纯图标控件必须有**无障碍名称**
- 交互目标至少 **40×40px**
- 必要标签**不得烤进背景图**
- 有意义图像给 alt，装饰图给空 alt
- 尽可能保证**脚本禁用时首屏仍可用**
- 尊重减少动效，**禁止自动播放音频**

## A.9 质量验收七问

1. **装饰被注意到之前，信息架构是否已经清晰可读？**
2. 是否**只有一个**家族在主导设计？
3. 每条线、每个代码、每个标签、每个动画**是否都有职责**？
4. 构图是否**非对称但平衡**？
5. 信号色与显示字体是否**克制到仍然有力**？
6. 竖屏版是**重新编排**的，还是被缩小的？
7. 产出是否原创、**没有复制专有资产**？

# 附录 C · 《明日方舟》UI/UX 分析要点

> 来源：[《明日方舟》UI/UX 分析——藏在好看背后的先进性](https://gameinstitute.qq.com/index.php/knowledge/100122)，作者 AJ（腾讯互娱）。这是目前能找到的、对谈方舟 UI 最系统的中文分析。

文章从六个角度切入，以下为与**本站实现直接相关**的要点。

## C.1 Diegetic Interface（画内界面）

与"画外界面"（只呈现给玩家的 HUD）相对，"画内界面"把**角色能看到的信息以相同方式呈现给玩家**，打破"隔着一个屏幕"的舒适区。

方舟的主看板就是典型案例：博士通过 **PRTS**（Prmitive Rhodesisland Terminal Service）远程接入，所以用"钢铁侠头盔内的漂浮投影界面"来表现这种状态。手机的电量、信号、时间被按统一风格放进浮窗，并随陀螺仪整体移动。

> **本站的对应**：启动动画的 PRTS 终端、`PERSONAL PAGE://` 前缀、等宽时间戳、`NN` 索引 —— 都在强化"你在操作一台终端"的虚构感，而不是"你在看一个网页"。

## C.2 类 Fluent Design 的多元质感

- **背景模糊（毛玻璃/亚克力）**是建立层级的核心手段；它不同于普通渐变，色彩结合更柔和，能与锐化过的正文形成对比
- 背景模糊还有个副作用：覆盖在旧页面之上时，让玩家**"窥见"下方被覆盖的层级**，降低对新页面的抗拒
- 方舟 UI 的突出特点是**层级对比度极高**

## C.3 扁平化之后的深度

- 扁平化的出发点是**减少与交互无关的细节**，不是"单纯地平"；理解错了会导致学习成本上升、画面失焦
- **暗角（vignette effect / 热点效应）**：原本是摄影中因遮光导致中心明度饱和度高于四周的现象，现代平面设计用它**突出页面中心**，方舟在多个页面用它来突出卡片
- 寻访界面的**视差**配合干员大小差异（暗示远近）建立透视感

> **本站的对应**：Hero 的径向暗角、`backdrop-filter: blur(14px)` 顶栏。

## C.4 装饰字体的双重表达

- 方舟页面给人"大量衬线体"的印象，但**衬线并不是游戏内最广泛的字型**；中文衬线因笔画粗细差异显著而具可读性，与悬浮视窗、工厂格纳库风插画形成统一的工业感
- 拉丁衬线的风格演变（Roman → Old-Style → Transitional → Modern）中，衬线与笔画粗细差越来越大、字肩弧度越来越平直 —— 说明"衬线=古典、无衬线=现代"的二分法**有偏颇**
- 基建系统中的 **Bender** 是"伪等距字体"（看上去像现代等距体，实际只有少部分字符等距），它的加入让工业系统硬核不少
- **中英结合**是刻意的装饰手法，几乎所有组件内都有英文

> **本站的对应**：`INDEX 首页`、`STACK 技术栈` 这类双语标签；`--display` / `--tech` / `--serif` 三套拉丁字体栈。

## C.5 底图处理：方舟的两种签名纹理

**这是本节最实用的一条。**

- **网点纸（halftone）**：散点型 = 低密度高颗粒度的 Grain，用于按钮可让留白不显单薄，用于卡片背景可提升对比度
- **粗条纹**：类似**警戒线**的风格，展现工业感
- 这两种底图处理"在游戏内外均以**惊人的统一性**被使用"
- 另有**局部马赛克化**，营造"失去同步"的信息暗示

> **本站的对应**：`--noise`（4% 噪点，对应散点）+ `--grid-4`（64px 蓝图网格）+ `--stripe`（45° 警戒线，用在区块标题标尺上）。**警戒线这一条最初漏掉了，是读本文后才补上的。**

## C.6 降低页面层级的过场技巧

- 每一个页面切换都有过场动画，且根据页面逻辑**针对性选择**：独立系统之间用简单深色淡出，有逻辑联系的关卡用明显的 zoom-in/out
- **堆叠浮窗**：次级系统直接在原页面之上呼出（签到、邮件、通知、设置），用背景模糊覆盖降低抗拒感
- **局部位移**：干员养成页里每个可点击项都不跳转到全新页面，而是保持与原页面的联系（横移淡入、人物位移、数值右展开、毛玻璃弹窗…），**玩家在复杂系统中一直没离开过同一张 canvas**

# 附录 E · 应用深度分级

> 同一份来源（`depth-levels.md`）。**深度衡量的是实现覆盖度与编排复杂度，不是内容密度。**

| 级别 | 名称 | 阶段层数 | 组件覆盖 | 动效 | 响应式 |
|---|---|---|---|---|---|
| 1 | minimal / 极简 | 0–1 | 关键 | 仅直接交互 | 安全堆叠 |
| 2 | moderate / 中等 | 1–2 | 共享主要 | 揭示 + 直接 | Shell 适配 |
| 3 | complex / 复杂 | 多区 | 广泛 | 协同编排 | 系统级参照 |
| 4 | maximal / 极繁 | 定制分节 | 全覆盖 | 状态驱动 | 完全重排 |

**选择规则**：用户指定深度则遵从；未指定时，**生产力/产品 UI 默认 moderate，游戏化/展示型 UI 默认 complex**。

**提升深度允许**：增加有意义的层、响应式重排、状态感知动效。
**提升深度绝不允许**：伪造遥测、重复文案、增加颜色、缩小必要文字、削弱无障碍。

> **本站定位：`moderate`。**
> 理由：本站是内容型个人站而非游戏化展示页；已具备多区 shell（顶栏 + 舞台 + 区块）、一层受控纹理/仪表层（噪点 + 网格 + 警戒线 + 角标括号）与克制的揭示动效。未做 `complex` 的多区协同编排。
